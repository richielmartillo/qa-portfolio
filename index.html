06 / APRENDIZADO

Aprenda QA — Seus primeiros passos em Qualidade de Software

Um espaço gratuito para compartilhar conhecimentos, conceitos e experiências práticas sobre testes de software. Aprenda os fundamentos de QA e descubra como começar a testar aplicações digitais.

Começar a aprender →

QA, ou Quality Assurance, é a área responsável por garantir que o software entregue ao usuário seja útil, confiável e seguro. Em vez de focar apenas em “achar erros no fim”, o objetivo é prevenir problemas durante o processo de criação.

Qual a importância da qualidade de software? Porque aplicações que quebram, demoram, confundem ou falham na rotina do usuário geram perda de confiança, retrabalho e custos maiores para a empresa.

Diferença entre QA e execução de testes: o QA envolve planejamento, análise de riscos, definição de critérios, revisão de requisitos e melhoria dos processos. A execução de testes é uma parte do QA, focada em validar o comportamento real do sistema.

O papel do QA Tester: observar o produto como um usuário, analisar requisitos, projetar cenários, executar testes e registrar evidências com clareza.

  • Exemplo do cotidiano: quando um site de compras não permite finalizar uma compra devido a um campo obrigatório esquecido, isso impacta a experiência e a confiança do cliente.
  • Exemplo prático: validar que o botão “Continuar” só funcione quando todos os campos necessários estiverem preenchidos.

Testes funcionais: validam se as regras do sistema funcionam como esperado.

Testes exploratórios: simulam a navegação livre do usuário para descobrir falhas inesperadas.

Testes de regressão: verificam se mudanças recentes não quebraram áreas já funcionando.

Testes de usabilidade: avaliam se a aplicação é intuitiva, clara e fácil de usar.

Introdução aos testes de API: validam contratos, códigos de resposta e regras de negócio em endpoints.

  • Exemplo funcional: login com usuário e senha válidos.
  • Exemplo exploratório: tentar navegar em um fluxo incomum para descobrir comportamento inesperado.
  • Exemplo de regressão: confirmar que a funcionalidade de busca continua funcionando após uma atualização visual.
  • Exemplo de usabilidade: verificar se o botão de checkout está visível e com texto claro.
  • Exemplo de API: confirmar que um pedido com dados inválidos retorna status 400.

Um caso de teste é um roteiro de verificação para validar um requisito ou comportamento. Ele deve ser claro, objetivo e reutilizável.

  • Pré-condições: o estado necessário para começar a execução.
  • Passos: sequência de ações realizadas.
  • Resultado esperado: o que deveria acontecer.
  • Resultado obtido: o que realmente aconteceu.
  • Status: aprovado, falhou, bloqueado ou não executado.

ID Objetivo Pré-condição Passos Resultado esperado Status
TC-01 Validar login com credenciais válidas. Usuário cadastrado e senha correta. 1. Acessar a tela de login.
2. Informar e-mail e senha.
3. Clicar em entrar.		 O usuário é autenticado e redirecionado ao painel. Passou

Um bug é qualquer comportamento que diverge do esperado e compromete a qualidade do produto. Para reportar bem, o QA precisa reproduzir, documentar e evidenciar o problema.

  • Como reproduzir: seguir os passos até que o defeito apareça.
  • Como documentar: registrar ambiente, versão, passos, evidências e impacto.
  • Severidade: impacto no negócio ou na operação do sistema.
  • Prioridade: urgência com que o defeito precisa ser corrigido.
  • Evidências: prints, vídeos, logs ou mensagens ajudam a validar e comunicar a falha.

Exemplo fictício de relatório de bug

Título: Login permite acesso com senha vazia.

Ambiente: Chrome 128, Windows 11, build 2.4.1.

Passos para reprodução: 1. Acessar a página de login. 2. Digitar e-mail válido. 3. Deixar o campo de senha em branco. 4. Clicar em “Entrar”.

Resultado esperado: O sistema deve bloquear o login e exibir mensagem de erro.

Resultado obtido: O sistema autentica o usuário e entra na conta.

Imagine que você está testando uma página de login. O sistema permite entrar mesmo quando o campo de senha está vazio.

  1. Qual é o comportamento incorreto?
  2. Qual seria o resultado esperado?
  3. Quais passos você usaria para reproduzir o problema?
  4. Como é melhor registrar esse defeito?

Resposta comentada:

O comportamento incorreto é permitir o login sem senha, mesmo com a regra de validação esperada. O resultado esperado seria apresentar uma mensagem de erro e impedir o acesso. Para reproduzir, basta abrir a página de login, preencher um e-mail válido, manter a senha em branco e clicar em entrar. Para registrar, escreva um título como “Login com senha vazia permite autenticação”, informe ambiente, passos, resultado esperado e obtido, e anexe evidências como print da tela.
